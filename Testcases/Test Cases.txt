## Test Case 1: Normal Input

**Objective:** Check that a valid order is added to a table.

**Steps:**
1. Run the program.
2. Choose option `1` (Take order).
3. Enter table: `5`
4. Enter order item: `Burger`
5. Enter quantity: `2`
6. Type `done`.

**Expected output:**
```
Burger x2 added to Table 5 | Amount: 200
```

**Actual output:**
```
Burger x2 added to Table 5 | Amount: 200
--- Running order: Table 5 ---
Burger x2 = 200
```

**Result:** Pass. The required line is displayed, and the running order is shown as an extra.

## Test Case 2: Boundary / Minimum Input

**Objective:** Check the smallest valid table number and quantity, and the bill calculation.

**Steps:**
1. Choose option `1`.
2. Enter table: `1`
3. Enter order item: `Coffee`
4. Enter quantity: `1`
5. Type `done`.
6. Choose option `3` (Generate bill) and enter table `1`.

**Calculation:**
- Subtotal = 50 x 1 = 50
- Service charge = 10% of 50 = 5.00
- GST = 5% of 50 = 2.50
- Total = 50 + 5.00 + 2.50 = 57.50

**Expected output:**
```
Subtotal: 50 | Service charge (10%): 5.00
GST (5%): 2.50 | Total: 57.50
```

**Actual output:**
```
Subtotal: 50
Service charge (10%): 5.00
GST (5%): 2.50
Total: 57.50
```

**Result:** Pass. The values match. They are printed on separate lines for a neater bill.

## Test Case 3: Invalid Input

**Objective:** Check that wrong inputs are rejected with the correct message and the program asks again instead of crashing.

### 3(a): Item not on the menu

**Steps:** Choose `1`, table `3`, order item: `Pasta`

**Expected output:**
```
Item not on the menu. Available: Burger, Pizza, Coffee
```

**Actual output:** Same as expected. The program asks for the order item again.

**Result:** Pass.

### 3(b): Invalid quantity

**Steps:** Choose `1`, table `3`, order item: `Burger`, quantity: `abc`

**Expected output:**
```
Invalid quantity. Enter a whole number.
```

**Actual output:** Same as expected. The program asks for the quantity again.

**Result:** Pass.

### 3(c): Invalid table number

**Steps:** Choose `1`, enter table: `0`

**Expected output:**
```
Invalid table number. Enter a number between 1 and 20.
```

**Actual output:** Same as expected. The program asks for the table number again.

**Result:** Pass.

**Extra invalid inputs also handled:** table `21`, table `-3`, table `abc`, quantity `0`, quantity `-2`, quantity `2.5`, and menu option `9`.

## Test Case 4: Different Valid Scenario

**Objective:** Check multiple items on one table and the full bill.

**Steps:**
1. Choose option `1`, enter table `3`.
2. Order item `Burger`, quantity `2`.
3. Order item `Pizza`, quantity `1`.
4. Order item `Coffee`, quantity `4`.
5. Type `done`.
6. Choose option `3`, enter table `3`.

**Calculation:**
- Burger: 100 x 2 = 200
- Pizza: 200 x 1 = 200
- Coffee: 50 x 4 = 200
- Subtotal = 600
- Service charge = 10% of 600 = 60.00
- GST = 5% of 600 = 30.00
- Total = 600 + 60 + 30 = 690.00

**Expected output:**
```
Burger x2 = 200 | Pizza x1 = 200 | Coffee x4 = 200
Subtotal: 600 | Service charge (10%): 60.00
GST (5%): 30.00 | Total: 690.00
```

**Actual output:**
```
========== BILL ==========
Table: 3
Burger x2 = 200 | Pizza x1 = 200 | Coffee x4 = 200
--------------------------
Subtotal: 600
Service charge (10%): 60.00
GST (5%): 30.00
Total: 690.00
==========================
```

**Result:** Pass.
